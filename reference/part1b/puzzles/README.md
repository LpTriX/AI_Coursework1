# Practice puzzles

Every puzzle in this folder was constructed locally with
[tools/make_puzzles.py](../tools/make_puzzles.py). Nothing was copied from an
external puzzle collection, so **no external difficulty rating is claimed for
any of these files**. Regenerate them at any time with:

```sh
python3 tools/make_puzzles.py
```

| File | Givens | Empty cells | Construction | Completions |
| --- | ---: | ---: | --- | ---: |
| `completed.txt` | 81 | 0 | closed-formula completed board | exactly 1 |
| `few_blanks.txt` | 76 | 5 | the same board with five scattered cells blanked | exactly 1 |
| `p1.txt` | 30 | 51 | shuffled board dug one cell at a time (seed 1, target 30 givens) | exactly 1 |
| `p2.txt` | 25 | 56 | shuffled board dug one cell at a time (seed 7, dug until no further cell could be removed) | exactly 1 |
| `unsolvable.txt` | 79 | 2 | givens rearranged so cell (0,0) sees all nine digits while no two givens conflict | 0 |

Notes:

- The completed board is generated by the closed formula
  `(3r + r//3 + c) mod 9 + 1`; every row, column and box holds each digit
  1-9 exactly once.
- `p1.txt` and `p2.txt` start from a deterministically shuffled copy of that
  board (seed 20261027). Cells are blanked one at a time in a seeded random
  order, and a cell stays blank only if the puzzle still has exactly one
  completion afterwards. This is the standard "dig holes" method: random
  subsets of a completed board are usually *not* unique because they miss
  small unavoidable sets (a 2x2 rectangle whose two values could be swapped
  already gives two completions), so removal has to be checked cell by cell.
  `p2.txt` stopped at 25 givens because every further removal created a
  second completion — it is locally minimal for that digging order.
- Uniqueness was verified with `solver.count_solutions` (limit 2), and the
  generator refuses to write a puzzle that fails the check.
- `unsolvable.txt` is valid input: no unit contains the same digit twice,
  so the program cannot reject it as a formatting error. Its first row
  holds 2-9 and its first column holds a 1, which leaves the corner cell
  with no legal digit. Finding "no solution" here is a search result, not
  an input check.
