## 当前实现阶段

已实现输入验证、MRV 回溯求解、命令行运行与搜索统计。单元测试使用标准库 unittest，独立检查结果的行、列、宫及原始给定数字。

在仓库根目录运行：

```sh
python3 reference/part1b/solver.py reference/part1b/puzzles/standard.txt --stats
python3 -m reference.part1b.solver reference/part1b/puzzles/branching.txt --stats
```

返回码：0 表示找到一个解；1 表示合法输入但无解；2 表示输入错误。返回一个解不代表证明唯一解。默认没有时间上限，最坏情况仍可能搜索很久。

在仓库根目录运行：

```sh
python3 -m unittest reference.part1b.test_solver -v
```

## 如何追踪代码

1. `read_puzzle` / `parse_puzzle`：文件和文本转换为棋盘。
2. `validate_board`：检查形状、数值和初始冲突。
3. `solve`：复制输入，建立每行/列/宫已用数字的位掩码。
4. 内部 `search`：计算每个空格的当前合法数字，发现空候选集合就返回失败；否则按 MRV 选择空格。
5. 尝试一个数字，递归；失败时撤销棋盘和三个掩码，再试其他候选。
6. `main`：打印解/无解消息及可选统计。

候选集合在每次搜索时重新计算，没有维护 AC-3 队列或持久化的 forward-checking 域表。不要把这份参考描述成实现了未包含的算法。

## 统计口径

| 字段 | 定义 |
| --- | --- |
| `nodes` | 进入一次递归 search 计一次，包含根、失败状态和成功终点 |
| `assignments` | 对选中空格尝试一个候选数字计一次 |
| `backtracks` | 子搜索失败后撤销一次候选赋值计一次 |
| `max_depth` | 同时填入的非给定数字的最大数量，根深度为 0 |
| `elapsed_seconds` | 初始输入验证后开始，包含搜索结构初始化和搜索；不含文件读取、输入验证和输出 |

MRV 并列时按行优先选择，数字按从小到大尝试。相同输入的解和计数可重复；计时会受环境影响。

## 输入

- 9 行，每行 9 个单数字；0 表示空格。
- TXT 使用空白分隔，CSV 使用逗号分隔。
- 文件末尾允许正常换行；额外空白行、少行、多行、非整数、越界数字和初始冲突会被拒绝。

## 练习数据

`standard.txt` 与 `branching.txt` 是本次会话转录的练习输入，没有经过外部来源、唯一性或正式难度认证。名称只是标识，不能直接当成报告中的难度分级或数据来源。

`unsatisfiable.txt` 是从规则生成的完整棋盘改造的反例：初始给定数字无直接重复，但不存在完整解。程序必须通过搜索/候选值检查判定无解，不能将其误归类为格式错误。

正式实验应使用你自行收集、可追溯来源的多个题目，并保存真实测量。
